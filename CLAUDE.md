Notes for Claude Code working in this repository. This file is public.

## What this repo is

mini-city-brain is a small transport-data platform that runs on one laptop with Docker. It replays public Victorian traffic-signal volume data as a stream of readings and moves them through:

- a FastAPI ingestion API,
- a queue on a local AWS emulator,
- object storage,
- DuckDB, dbt models, a scheduled pipeline with data-quality checks,
- metrics and a baseline forecast.

Everything is free: no paid service, no real cloud account, no credit card.

## Hard rules

1. **Git is the owner's job.** Never run `git add`, `git commit`, `git push`, `git config`, `git rm`, `git mv`, `git reset --hard`, `git checkout`, `git switch`, `git restore`, `git clean`, `git stash`, `git rebase`, `git pull`, `git merge`, `git branch -m` or `-D`, or any `gh` command that changes GitHub.
   - Read-only git is fine: `status`, `diff`, `log`, `show`, `ls-files`, `grep`, `check-ignore`.
   - Delete or move files with plain `rm` and `mv`; the owner stages them.
2. **Local-only files.**
   - Files listed in `.git/info/exclude` are local only. You may write `PROGRESS.md`, `REPORT.md`, `COMMIT_PLAN.md` and `review.zip`.
   - Never copy text from any local-only file into a tracked file.
   - `.preflight-terms` lists words that must never appear in tracked files or commit messages. Read it before writing anything. If it is missing, record that in `PROGRESS.md` and do not write `COMMIT_PLAN.md`.
3. **No real cloud.**
   - Every AWS SDK client and the Terraform provider point at the local emulator through `AWS_ENDPOINT_URL`, with the dummy credentials `test`/`test`.
   - Never read `~/.aws`, never use real credentials, never remove the endpoint overrides.
   - Describe this as a "local AWS emulator", never as AWS experience or an AWS deployment.
4. **Data.**
   - Public data only, with the licence recorded in `docs/data.md`.
   - Never commit raw or downloaded data. `data/` and `site/data/` are gitignored.
   - Never download real data on this machine. The only download path is the GitHub Pages workflow, inside the runner, when the repository variable `REAL_DATA_ENABLED` is `true`.
   - Test fixtures are synthetic, generated by a script with a fixed seed, and stay under 200 KB each.
5. **Numbers.**
   - Every number in the README or docs carries one label: `measured (host CPU)`, `measured (CI runner)`, `estimated (tool)`, `simulated`, `vendor-published` or `not measured`.
   - Every measured number comes from a run whose output is saved under `results/` or visible in a CI log.
   - Numbers from synthetic data are `simulated` and never appear as headline results.
6. **Words.**
   - Direct, concrete, no buzzwords, no emojis, no hype.
   - Do not write "real-time", "production-grade" or "scalable" without saying exactly what is meant (for example "replayed at 60x speed").
   - The README keeps its "How AI was used and verified" section, which links to `docs/ai-log.md`.
7. **Dependencies.**
   - Pin exact versions of Python packages, Docker images and GitHub Actions. Prefer releases at least 14 days old.
   - Record each licence in `docs/third-party.md`.
8. **Decisions.** When a choice is unclear, take the conservative option, add an entry to `docs/decisions.md` (ID, date, choice, reason, how to revert) and continue.

## Layout

Matches the repository as of the 2026-11-10 rebuild.

```
services/api/        FastAPI app: ingest, forecast, health, metrics
services/worker/     queue consumer: validates, batches, writes ndjson to object storage
services/common/     reading model, settings, AWS clients, JSON logging
ingest/              SCATS reader, synthetic generator, replay client
warehouse/           loader from object storage into DuckDB
transform/           dbt-duckdb project (staging, marts, tests)
orchestration/       Dagster job, blocking checks, command-line runner
forecast/            baseline forecasts and their evaluation
infra/terraform/     buckets and queues, pointed at the local emulator
site/                static demo page (plain HTML/JS), exporter (run as a script), JSON schema
observability/       Prometheus config, Grafana provisioning and dashboard JSON
tests/               pytest suites and a small synthetic fixture
docs/                data.md, decisions.md, third-party.md, testing.md, demo.md, ai-log.md
docs/media/          diagram (architecture.svg), hero illustration (hero-isometric.svg); the demo GIF is added by the owner
scripts/             preflight, review bundle, demo, Pages build and helper scripts
results/             saved outputs of runs that numbers in the docs come from
requirements/        pinned dependencies (direct.txt, constraints.txt, per-image files)
```

Notes:

- `site/` must not become a Python package: a package called `site` clashes with the standard library. Run `python site/export.py`.
- `orchestration/definitions.py` must not use `from __future__ import annotations` (Dagster reads context type hints as real types).
- Python 3.13.5 for the virtual environment, CI and Docker images (decisions D18). `pyproject.toml` keeps `requires-python >= 3.12`; 3.12 is untested.
- During the rebuild, tests and lint ran from a virtual environment outside the repo folder because imports from a OneDrive folder hung (decisions D23). The repo now lives outside OneDrive and `make setup` creates `.venv` in it. `make VENV=<path> ...` still works.

## Commands

Status of each as of 2026-11-17. "Run" means it was run on the owner's laptop (macOS, Docker Desktop) and passed.

```
make setup       # create venv, install pinned dependencies (run, in a scratch venv from the same files)
make lint        # ruff check and ruff format --check (run)
make test        # pytest; unit tests use an in-process Moto emulator, no Docker (run)
make up / down   # docker compose stack; down also stops the obs profile (run)
make replay      # replay synthetic data into a running API (run)
make pipeline    # Dagster job once: load -> dbt build -> blocking checks (run, synthetic data)
make site        # write site/data/summary.json from the warehouse (run through the tests)
make demo        # stack up, replay 2 synthetic days for 5 sites, run pipeline, print URLs (run)
make demo-bad    # inject faulty data; the pipeline must fail readably (run; exits non-zero by design)
make demo-down   # stop the stack and remove volumes (run)
make dagster-ui  # Dagster UI on port 3001 (run; served HTTP 200, not opened in a browser)
make preflight   # bash scripts/preflight.sh --tree (run)
make review-bundle  # bash scripts/make_review_bundle.sh (writes review.zip, local only)
```
